# בדיקות Windows ידניות לפני Release רשמי

המסמך מיועד לבדיקות שאוטומציה ב-GitHub Actions אינה יכולה להחליף: פתיחת הממשק בפועל, התנהגות המתקין על Windows אמיתי, ובדיקת עומס ממושכת על מחשב חלש.

**לא ליצור תג גרסה ולא לפרסם Release רשמי לפני שכל הבדיקות המסומנות כחובה מסתיימות בהצלחה.**

## קובצי בדיקה זמינים

המאגר פרטי; יש להיכנס לחשבון GitHub בעל הרשאה למאגר.

מתוך [Windows CI run #82](https://github.com/IS-IVR/ram-sentinel/actions/runs/45666021480) אפשר להוריד:

- `ram-sentinel-win-x64` — יישום Windows עצמאי.
- `ram-sentinel-inventory-soak-win-x64` — כלי מדידת עומס ל-30 דקות.
- `ram-sentinel-release-assets` — מתקין זמני, ZIP נייד וקובץ SHA-256 שנבנו לפני המעבר לבניית חבילות מתגי גרסה בלבד.

הארטיפקטים זמניים ועשויים לפוג בהתאם למדיניות השמירה של GitHub Actions. הם אינם Release רשמי.

## A. בדיקת התקנה והסרה

**חובה לפני Release ראשון.**

1. הורד וחלץ את `ram-sentinel-release-assets`.
2. הפעל את `RAM-Sentinel-Setup-0.0.0-ci-win-x64.exe` כמשתמש Windows רגיל. אין לבחור Run as administrator.
3. בחר עברית במסך בחירת השפה.
4. השאר את תיקיית ברירת המחדל תחת `%LOCALAPPDATA%\Programs\RAM Sentinel`.
5. השלם את ההתקנה. בדוק שנוצר קיצור דרך בתפריט התחלה ושאפשר להפעיל ממנו את RAM Sentinel.
6. ודא שלא נדרשה הרשאת מנהל ולא הופיע מסך UAC.
7. פתח את הגדרות Windows > אפליקציות > אפליקציות מותקנות וודא שמופיע ערך הסרה של RAM Sentinel.
8. הסר את התוכנה דרך Windows. ודא שהתיקייה וקובץ `RamSentinel.exe` הוסרו ושערך ההסרה נעלם.

אין צורך לסמן הפעלה אוטומטית עם הכניסה ל-Windows. אין לשנות הגדרות Startup במהלך בדיקת המתקין.

## B. בדיקת הממשק בפועל

**חובה לפני Release ראשון.**

הפעל את `RamSentinel.exe` מתוך הארטיפקט `ram-sentinel-win-x64`, או לאחר התקנה מוצלחת.

| בדיקה | תוצאה צפויה |
|---|---|
| פתיחת התוכנה | החלון נפתח ללא קריסה וללא בקשת הרשאות מנהל |
| שפה וכיווניות | טקסט בעברית, יישור RTL קריא, מספרים ואחוזים מוצגים בסדר תקין |
| מדדי מערכת | RAM כולל, בשימוש, זמין, Cache, Commit, CPU, השהיית דיסק ושטח פנוי מוצגים או מסומנים "לא זמין" |
| איסוף ראשוני | מסך האבחון מציג הודעה שאוספים מדידות; אין דרישה לבצע פעולה על סמך דגימה בודדת |
| עדכון נתונים | המדדים מתעדכנים לאורך כמה מחזורי ניטור, בלי קפיצות שגויות או קריסה |
| אבחון | מוצג לכל היותר ממצא עיקרי ועד שני ממצאים נוספים; כאשר אין מספיק ראיות מוצג מצב איסוף/אין צוואר בקבוק מתמשך |
| תהליכים | הרשימה מציגה תהליכים ומדדי CPU/RAM זמינים; ערך חסר אינו מוצג כאפס |
| תוכנות הפעלה | הרשימה מציגה מקור ופקודת הפעלה; מופיעה ההבהרה שההשפעה עדיין לא נמדדה |
| אזור התראות | הכפתור "העבר לאזור ההתראות" מסתיר את החלון ומשאיר את סמל התוכנה באזור ההתראות |
| חזרה לחלון | לחיצה כפולה על סמל התוכנה פותחת את החלון מחדש |
| סגירת חלון | לחיצה על X מסתירה את החלון; יציאה מלאה נעשית דרך תפריט סמל התוכנה |

השווה מדדי RAM ו-CPU מול מנהל המשימות של Windows. רשימת התהליכים בתוכנה מציגה רק את הפריטים המובילים, ולכן אין לצפות שתהיה זהה לרשימה המלאה במנהל המשימות.

**אין לבצע בבדיקה הזו:** ניקוי זיכרון, מחיקת קבצים, השבתת שירותים, שינוי Page File או שינוי רכיבי אבטחה.

### בדיקה אופציונלית של בקשת סגירה רגילה

אפשר לפתוח Notepad, לכתוב טקסט שלא נשמר, לבחור אותו ברשימת התהליכים ולבקש סגירה רגילה. התוצאה התקינה היא הצגת בקשת שמירה של Notepad, בלי סגירה כפויה. לבדיקת ביטול, בחר ביטול בחלון השמירה. אל תבצע בדיקה זו על תהליך מערכת או תוכנה עם עבודה חשובה.

## C. בדיקת עומס של 30 דקות

**חובה לפני הפעלת המלצות Lifecycle ולפני Release ראשון של האינטגרציה.**

1. חלץ את `ram-sentinel-inventory-soak-win-x64` לתיקייה רגילה.
2. פתח CMD באותה תיקייה.
3. הרץ כמשתמש רגיל, ללא הרשאות מנהל:

```cmd
RamSentinel.InventorySoak.exe --duration-minutes 30 --interval-seconds 30 --output "%USERPROFILE%\Desktop\ram-sentinel-soak.csv"
```

4. המשך להשתמש במחשב כרגיל במשך 30 דקות. אל תסגור בכוונה תוכנות רק כדי לשנות את מספר התהליכים.
5. בסיום שמור את `ram-sentinel-soak.csv`.

בדוק במיוחד:

- זמן איסוף ממוצע, P95 ומקסימום.
- CPU וזיכרון של כלי המדידה עצמו.
- האם הזיכרון של כלי המדידה נשאר יציב.
- שיעור דגימות Toolhelp במצב Complete.
- שיעור `relationships_ready` והאם הדגימות החלקיות גורמות להשהיות תכופות מדי.

אין להחליש את דרישות שלמות הנתונים רק כדי לשפר את שיעור ההצלחה. אם שיעור הדגימות השלמות נמוך, יש לחקור את סיבת המרוץ לפני שינוי הקוד.

ה-CSV מתוכנן להכיל מדדים מצטברים בלבד, ללא PID, שמות תהליכים, נתיבים, כותרות חלונות או תוכן משתמש. יש לבדוק זאת לפני שיתוף הקובץ.

## D. דיווח תוצאות

יש לתעד ב-Issue #9 או כתגובה ל-PR #8:

- דגם המחשב וגרסת Windows.
- האם ההתקנה וההסרה הצליחו.
- האם הממשק נפתח והציג נתונים לאורך זמן.
- האם היו קריסות, הודעות שגיאה או מדדים שנראו לא סבירים.
- תוצאת בדיקת העומס: משך, מספר דגימות, שיעור Complete, ממוצע/P95/מקסימום של זמן איסוף.
- לצרף את CSV המדידה רק לאחר בדיקת תוכנו.

אם בדיקה נכשלת, יש לתעד את הכשל ולתקן אותו לפני Release. אין לסמן בדיקה ידנית כעברה על בסיס הצלחת GitHub Actions בלבד.

## גבולות בטיחות

הבדיקות אינן משנות הגדרות Windows, אינן משביתות שירותים ואינן סוגרות תהליכים אוטומטית. המלצות Lifecycle נשארות כבויות עד להשלמת בדיקות ה-UI וה-Soak ואישור התוצאות.
