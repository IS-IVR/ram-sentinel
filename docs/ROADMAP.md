# Roadmap - RAM Sentinel

## שלב 0 - ניטור וניהול בטוח

- [x] מבנה Solution ופרויקטים.
- [x] מדידת RAM באמצעות GlobalMemoryStatusEx.
- [x] מדידת Commit, Cache, Kernel Nonpaged ומספר תהליכים באמצעות GetPerformanceInfo.
- [x] זיהוי Normal / Warning / High עם לחץ קריטי למשך 30 שניות.
- [x] חלון Tray בעברית.
- [x] רשימת 20 תהליכים לפי Working Set ו-Private Memory.
- [x] בקשת סגירה רגילה של אפליקציית משתמש לאחר אישור ואימות זהות התהליך.
- [x] התראה בעת לחץ זיכרון מתמשך.
- [x] הפעלה אוטומטית אופציונלית למשתמש הנוכחי.
- [x] בדיקות לוגיקה בסיסיות ל-MemoryPressureEvaluator.
- [x] GitHub Actions עם Build, בדיקות ו-Publish.
- [ ] בדיקת Build והרצה על Windows 11 במחשב פיזי.
- [ ] מדידת צריכת RAM/CPU של התוכנה עצמה לאורך 24 שעות.
- [ ] בדיקה על 4GB / 8GB / 16GB RAM.

## שלב 1 - אבחון עומס אמיתי

- [ ] היסטוריית RAM ו-Commit לאורך 10-30 דקות.
- [x] מדידת CPU מערכתית לפי Delta של GetSystemTimes.
- [ ] מדידת CPU לכל תהליך לפי Delta של זמן מעבד.
- [ ] מדידת פעילות דיסק והבחנה בין עומס דיסק לבין Paging.
- [ ] זיהוי תהליך שצריכת הזיכרון הפרטית שלו גדלה ברציפות.
- [ ] הצגת הסבר מדוע התוכנה ממליצה על פעולה מסוימת.
- [ ] ספי לחץ ניתנים להגדרה עם ברירות מחדל שמרניות.

## שלב 2 - אופטימיזציה בטוחה

- [ ] מנהל Startup Apps למשתמש הנוכחי בלבד.
- [ ] שמירת הגיבוי של פריטי Startup לפני השבתה, עם אפשרות Restore.
- [ ] המלצות מבוססות מגמה ולא רק צילום רגעי.
- [ ] כללי משתמש לתוכנות שמותר להציע לסגירה.
- [ ] אפשרות לסגירה רגילה בלבד, תמיד עם אפשרות ביטול/אישור.
- [ ] לא להוסיף סגירה כפויה או ניקוי Cache אוטומטי.

## שלב 3 - פרופילי עבודה

- [ ] פרופיל עבודה רגילה: ניטור חסכוני.
- [ ] פרופיל עומס: תדירות ניטור מעט גבוהה יותר רק בעת לחץ אמיתי.
- [ ] פרופיל משחק/תוכנה כבדה: התראות שקטות, ללא פעולות רקע שמפריעות.
- [ ] מנגנון שמוודא ש-RAM Sentinel עצמה אינה הופכת לצרכן משאבים משמעותי.

## שלב 4 - הפצה

- [ ] Publish עצמאי x64.
- [ ] בדיקת SmartScreen וחתימת קוד אם יוחלט להפיץ.
- [ ] מתקין והסרה נקייה.
- [ ] עדכונים מאומתים ומנגנון Rollback.

## עקרונות שלא משתנים

1. מהירות עבודה בפועל חשובה יותר ממספר RAM פנוי.
2. Windows רשאית לנהל Cache ו-Standby Memory.
3. לא מבצעים ניקוי זיכרון אגרסיבי רק כדי לשנות מדדים.
4. לא מסיימים תהליכים או שירותים בכוח.
5. כל אופטימיזציה חייבת להתבסס על מדידה ולהיות ניתנת לביטול.
6. אם צוואר הבקבוק הוא CPU, דיסק, GPU, חום או רשת, התוכנה צריכה לזהות זאת ולא להעמיד פנים שפינוי RAM יפתור הכול.

## תנאי קבלה לפני הפעלה קבועה

- Build ובדיקות CI עוברים.
- האפליקציה נשארת יציבה לפחות 24 שעות.
- אין זליגת זיכרון בתוכנת הניטור.
- צריכת CPU נמוכה בזמן ניטור רגיל.
- לא מתבצעת פעולה אוטומטית העלולה לגרום לאובדן עבודה.
