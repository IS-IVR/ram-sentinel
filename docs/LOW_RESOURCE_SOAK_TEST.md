# בדיקת עומס לאיסוף התהליכים (Windows)

## מטרה

למדוד את העלות של מחזור איסוף התהליכים ב-RAM Sentinel על מחשב Windows אמיתי, ובפרט על מחשב חלש או עם מעט RAM. הבדיקה מודדת משך איסוף, CPU וזיכרון של כלי המדידה, מספר תהליכים ומידת ההצלחה של צילום Toolhelp.

הכלי אינו מבצע אופטימיזציה או שינוי במחשב. הוא קורא נתונים בלבד.

## הורדה והפעלה

הורד את הארטיפקט המוכן: [ram-sentinel-inventory-soak-win-x64 (GitHub Actions #76)](https://github.com/IS-IVR/ram-sentinel/actions/runs/45609176862/artifacts/15018128578). זהו ZIP של כלי עצמאי ל-Windows x64.

1. חלץ את קובץ ה-ZIP לתיקייה רגילה.
2. פתח CMD באותה תיקייה והרץ:

```cmd
RamSentinel.InventorySoak.exe --duration-minutes 30 --interval-seconds 30 --output "%USERPROFILE%\Desktop\ram-sentinel-soak.csv"
```

אין צורך בהרצה כמנהל. מדדים שלא ניתן לקרוא בהרשאות המשתמש יסומנו כלא זמינים. מומלץ להריץ בזמן שימוש רגיל במחשב, בלי לסגור בכוונה תוכנות שהן חלק מסביבת העבודה הרגילה.

לבדיקה קצרה בלבד:

```cmd
RamSentinel.InventorySoak.exe --once
```

אפשר לעצור בכל שלב באמצעות `Ctrl+C`. הדגימות שכבר נכתבו יישארו בקובץ. אם קובץ היעד כבר קיים, הכלי לא ידרוס אותו; יש לבחור שם חדש.

## מה נמדד

- משך כל איסוף במילישניות, כולל ממוצע, P95 ומקסימום.
- CPU של תהליך כלי המדידה בזמן האיסוף.
- Working Set ו-Private Bytes של כלי המדידה עצמו.
- גודל Heap מנוהל של כלי המדידה.
- מספר התהליכים שנמצאו ומספר הרשומות שנקלטו.
- מספר ערכי Working Set שנקראו בהצלחה וסכום ה-Working Set שנצפה.
- מצב שלמות Toolhelp, מספר רשומות Parent PID והאם הדגימה עומדת בשער האמינות של קשרי תהליכים.

`observed_working_set_mb` הוא סכום המדדים הזמינים של התהליכים שנקלטו, ולא מדידה חלופית ל-RAM הפיזי הכולל של Windows. מדד הזיכרון של כלי המדידה עצמו מופרד ממנו.

## פרטיות

ה-CSV אינו כולל PID, שמות תהליכים, שמות משתמש, נתיבי קבצים, שורות פקודה, כותרות חלונות, תוכן דפדפן או קלט משתמש. הוא מכיל מספרים מצטברים, חותמות זמן ומצבי הצלחה בלבד. הקובץ נשמר מקומית ולא נשלח לשום שרת.

## הערכת תוצאות

אין להגדיר סף ביצועים שרירותי לפני מדידה על מחשב היעד. יש לבדוק:
- האם זמן האיסוף נשאר קטן משמעותית ממרווח הדגימה.
- האם CPU וזיכרון של כלי המדידה נשארים יציבים לאורך זמן.
- האם שיעור `Complete` של Toolhelp ושיעור `relationships_ready` נשארים סבירים בזמן פעילות רגילה.
- האם יש קפיצות או דפוס גדילה מתמשך בזיכרון או בזמן האיסוף.

שיעור נמוך של דגימות שלמות בזמן עומס תהליכים עשוי להעיד על מרוץ טבעי בין יצירה/סגירה של תהליכים לבין צילום Toolhelp. אין להחליש את שער האמינות רק כדי להעלות את האחוז; יש לנתח את הסיבה תחילה.

## בניית הכלי

```powershell
dotnet build .\ram-sentinel.sln --configuration Release
dotnet publish .\tools\RamSentinel.InventorySoak\RamSentinel.InventorySoak.csproj --configuration Release --runtime win-x64 --self-contained true -p:PublishSingleFile=true
```
