# מפרט UX - ממשק בסגנון סייר הקבצים של Windows 11

## 1. עיקרון עיצוב

הממשק צריך להרגיש כמו כלי Windows מובנה: שקט, מסודר, צפוי, עם Sidebar קבוע, סרגל פקודות, Breadcrumbs ורשימות פרטים. אין לבנות Dashboard עמוס בגרפים, כרטיסיות ענק או עשרות מדדים.

מטרת הממשק היא לעזור למשתמש להבין:
1. מה מאט את המחשב.
2. למה המערכת חושבת כך.
3. מה כדאי לעשות.
4. מה הסיכון ומה ניתן לשחזר.
5. האם הפעולה באמת שיפרה את הביצועים.

## 2. מבנה החלון

### Title Bar
- שם האפליקציה RAM Sentinel.
- כפתור תפריט/ניווט.
- תיבת חיפוש כללית: "חפש תהליך, תוכנת הפעלה או פעולה".
- כפתור עזרה קטן.
- התאמה ל-Light / Dark של Windows.

### Navigation Pane - Sidebar
רשימת ניווט קבועה בסגנון Explorer:

- **בית** - מצב המחשב והמלצה ראשית.
- **אבחון ביצועים** - ממצאי RAM / CPU / Disk / Startup / Storage.
- **תהליכים** - רשימת תוכנות ותהליכים.
- **תוכנות הפעלה** - מה מופעל עם Windows.
- **אחסון** - כוננים ושטח פנוי.
- **פעולות שבוצעו** - היסטוריה ו-Restore.
- **הגדרות** - תדירות ניטור, התראות, שפה, ערכת נושא ופרטיות.

בחלק התחתון: מצב ניטור, גרסת תוכנה והגדרות.

### Command Bar - סרגל פקודות
סרגל עליון שמשתנה לפי העמוד:
- סריקה / אבחון מהיר.
- רענון.
- סינון.
- מיון.
- פעולות עבור פריט שנבחר.
- תפריט "עוד".

פעולות מסוכנות אינן מוצגות ככפתור ראשי גדול. הן יופיעו רק לאחר בחירת פריט ותצוגת הסבר.

### Breadcrumb Bar
מיקום המשתמש מוצג בדומה ל-Explorer:
`בית > אבחון ביצועים > דיסק`
הוא מאפשר לחזור לרמה קודמת בלי לחפש בתפריטים.

### Main Content
אזור התוכן המרכזי. ברירת המחדל היא רשימה מפורטת וקומפקטית, לא גריד של כרטיסים גדולים.

### Details Pane
לוח פרטים בצד ימין או שמאל לפי RTL:
- תיאור הפריט.
- מדדים רלוונטיים.
- למה הוא מוצג.
- רמת ביטחון.
- פעולה מוצעת.
- סיכון / השפעה.
- כפתור שחזור או ביטול, כשאפשר.

לוח הפרטים יוכל להיסגר כדי להרחיב את הרשימה.

## 3. עמוד בית

בראש העמוד:
- כותרת "מצב המחשב".
- מצב ברור: תקין / נמצאה בעיה / אוספים נתונים.
- כפתור "אבחון מהיר".
- שעה שבה בוצעה המדידה האחרונה.

לאחר מכן:
- **הגורם העיקרי שמאט את המחשב**: finding אחד בלבד, עם הסבר פשוט.
- **מה ניתן לשפר**: עד שלוש המלצות, ממוינות לפי תועלת ובטיחות.
- **משאבי המחשב עכשיו**: RAM, CPU, Disk, Storage. מדדים קטנים ושקטים.
- **פעולות אחרונות**: פעולות שבוצעו והאם נמדד שיפור.

אין להציג מדד אדום רק כי הוא גבוה. צבע אזהרה מחייב Finding שנתמך בראיות.

## 4. עמוד אבחון ביצועים

רשימה דמוית Explorer עם שורות:
- קטגוריה.
- מצב.
- רמת ביטחון.
- מה נמדד.
- משך המצב.
- פעולה מומלצת.

פילטרים:
- הכול.
- דורש תשומת לב.
- RAM.
- CPU.
- דיסק.
- תוכנות הפעלה.
- אחסון.

בחירת Finding פותחת Details Pane עם פירוט הראיות והמלצה.

במהלך אבחון:
- ProgressBar.
- שלב נוכחי במילים פשוטות.
- אפשרות לעצור.
- המשך שימוש רגיל במחשב.
- אין להריץ כמה סריקות כבדות במקביל.

## 5. עמוד תהליכים

תצוגת Details עם מיון וסינון, בדומה לרשימת קבצים:
- שם התהליך / אייקון.
- CPU.
- RAM פיזי (Working Set).
- זיכרון פרטי.
- Disk I/O, כאשר זמין.
- חלון/רקע: רק אם ניתן לזהות בצורה אמינה.
- Publisher/Path רק לאחר בחירה או דרישה, ולא לסרוק קבצים ללא צורך.

פילטרים מהירים:
- CPU גבוה.
- RAM גבוה.
- פעילות דיסק.
- אפליקציות משתמש.
- תהליכי מערכת (קריאה בלבד).

בחירת תהליך מציגה פרטים, משך פעילות, מקור התהליך ופעולה אפשרית. "בקש סגירה רגילה" יופיע רק כשזו אפליקציית משתמש מתאימה; אין Kill.

## 6. עמוד תוכנות הפעלה

רשימת פריטים עם:
- שם.
- Publisher (אם נבדק).
- מקור: HKCU / HKLM / Startup Folder / Scheduled Task.
- מצב: מופעל / מושבת / לא ידוע.
- Impact: נמדד / לא נמדד.
- פקודת הפעלה / יעד.
- תאריך גיבוי/שינוי.

מיון:
- השפעה מדודה.
- שם.
- מקור.
- מופעל.

כפתורים:
- רענן.
- פתח הגדרות Startup של Windows.
- בהמשך: השבת פריט נבחר / שחזר.

הפעלה והשבתה נעשות רק אחרי Dialog שמסביר:
- מה יקרה.
- איך זה עשוי לשפר.
- מה יפסיק לפעול.
- איך לשחזר.
- איזה גיבוי נשמר.

## 7. עמוד אחסון

תצוגת כוננים אופקית/רשימת Details:
- אות כונן.
- סוג כונן אם זמין.
- קיבולת.
- פנוי.
- אחוז פנוי.
- זמני תגובה, אם נאספים.

קיצורי דרך:
- פתח Storage Settings.
- פתח Storage Sense.
- פתח Optimize Drives.

לא מוחקים קבצים מתוך עמוד זה בגרסה הראשונה.

## 8. עמוד פעולות שבוצעו

טבלה:
- תאריך ושעה.
- פעולה.
- מה השתנה.
- תוצאה.
- שיפור שנמדד.
- כפתור Restore.

כל פעולה הפיכה מציגה Restore. אם אין דרך בטוחה לשחזר, לא מציגים אותה כאופטימיזציה אוטומטית.

## 9. שפה חזותית

- Windows 11 Fluent design.
- Mica כבסיס חלון, עם fallback לצבע אחיד.
- Corner radius מתון, ללא כרטיסיות מיותרות.
- Fluent icons עקביים.
- שימוש בצבעי המערכת ל-Light/Dark/High Contrast.
- אנימציות קצרות בלבד; ניתן לכבות.
- לא להשתמש ב-transparency/Acrylic כבד על משטחים גדולים.
- טקסט קצר, כותרות ברורות ופעולות בשפה פשוטה.

## 10. עברית, נגישות והתאמה למסכים

- RTL מלא בכל הרכיבים.
- אין לערבב סדר של מספרים, אחוזים ונתיבים.
- תמיכה ב-100%, 125%, 150%, 200% DPI.
- ניווט מלא במקלדת.
- Focus indicator ברור.
- צבע אינו הדרך היחידה להצגת מצב.
- ניגודיות ו-High Contrast.
- חלון מינימלי שמיש גם ברוחב נמוך.
- Sidebar מתקפל אוטומטית בחלונות צרים.

## 11. רכיבי UI מומלצים

במקרה שנבחר WinUI 3:
- NavigationView לסרגל הניווט.
- TitleBar לכותרת ופעולות ניווט.
- CommandBar לפקודות.
- BreadcrumbBar למיקום.
- AutoSuggestBox לחיפוש.
- ListView עם Grid row template לרשימות Details.
- InfoBar להודעות מצב.
- ContentDialog לאישורי פעולות.
- MicaBackdrop לבסיס החלון.

## 12. תקציב ביצועים של הממשק

- אין אנימציות רקע.
- אין גרפים שמתעדכנים בכל שנייה כשהחלון מוסתר.
- Virtualization לרשימות.
- טעינת פרטים רק לאחר בחירת פריט.
- איסוף נתונים ב-Background Tasks ולא ב-UI Thread.
- הצגת מסגרת הממשק מיד; טעינת נתונים בהדרגה.
- אין סריקה בזמן פתיחת כל עמוד אלא בעת הצורך.
- מדידת Startup/Working Set של האפליקציה עצמה לפני בחירת Framework סופית.
