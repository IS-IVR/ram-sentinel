# תשתית Process Lifecycle Core

## מה נוסף

- `ProcessIdentity`: זהות של מופע תהליך לפי PID וזמן יצירה. PID לבדו אינו מזהה יציב.
- `ProcessLifecycleObservation`: צילום מצב לקריאה בלבד. ערכים שאינם זמינים נשארים null.
- `ProcessRelationshipTracker`: מזהה קשר הורה-ילד רק כאשר שני מופעי התהליך נצפו יחד בשתי דגימות רצופות.

## כללי שמרנות

- קשר שלא נצפה ישירות אינו נוצר בדיעבד.
- תהליך הורה שאינו מופיע באותה דגימה אינו מקושר לפי PID ישן.
- PID כפול באותה דגימה נחשב עמום.
- שימוש חוזר ב-PID יוצר זהות חדשה ואינו ממשיך קשר קודם.
- תהליך הורה חייב להיות קיים לפני תהליך הילד; קשר שבו ההורה נוצר מאוחר יותר מהילד נדחה גם אם אותו PID מופיע בשתי דגימות.
- זמן יצירת תהליך עתידי ביחס לזמן הדגימה נחשב נתון לא תקין.
- דגימה כפולה או ישנה אינה מגדילה את רמת הביטחון.
- פער גדול משתי דקות מאפס את רצף התצפיות.
- שתי תצפיות מעניקות Confidence בינוני; שלוש ומעלה מעניקות Confidence גבוה.
- הקשר אינו הוכחה לכך שתהליך הילד מיותר או שניתן לסגור אותו.

## גבולות הגרסה

זו שכבת Core בלבד. היא אינה אוספת מידע מ-Windows בעצמה, אינה מאזינה לחלון הקדמי, אינה מציגה התראות ואינה מבצעת פעולות על תהליכים. השלבים הבאים יוסיפו Provider ו-Foreground tracking תוך שימוש במחזור הדגימה הקיים, ולא בלולאת סריקה נוספת.
